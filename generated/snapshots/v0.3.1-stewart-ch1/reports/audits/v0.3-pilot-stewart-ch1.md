## 2. Architectural validation — what worked

1. **Two-layer dependency model held.** `statement.depends_on`
   (definitional/structural) cleanly separated from `proof.uses`
   (logical citations). 73 + 15 + 7 edges with no cross-pollution.
2. **`special_case_of` placement convention is unambiguous in
   practice.** Recording on the special node (polynomial → rational,
   rational → algebraic, natural-exp → exp, natural-log → log,
   horizontal-line-test → one-to-one as `equivalent`) produced a
   coherent partial order. Six edges, no contradictions.
3. **Iff proofs via `Proof.parts[]` (kind: `direction`).** Used in
   vertical-line-test and horizontal-line-test. Captures the two
   logical directions without inflating proof count.
4. **Bundle props (Type-A) via `Proof.parts[]` (kind: `case`).**
   Used for laws-of-exponents (4 laws), laws-of-logarithms (3 laws),
   cancellation-equations (2 identities). One node per bundle, one
   proof, parts inside. Avoided 9 spurious sibling nodes.
5. **`style: assumed` correctly captured epistemic debt** for
   laws-of-exponents — Stewart asserts without proof; the proof
   node exists to record the unproven citation chain that propagates
   downstream (laws-of-logarithms, change-of-base depend on it).
6. **`status: not_applicable` for prose-only statements** worked for
   geometric criteria: vertical-line-test, horizontal-line-test,
   inverse-graph-reflection, definition.algebraic-function,
   definition.transcendental-function, definition.trigonometric-function.
   No artificial LaTeX was forced.
7. **Snapshot rerun architecture validated.** `mkg-build →
   mkg-snapshot → mkg-diff` ran without modification; the diff
   correctly partitioned kept/added/removed.

## 3. Audit findings (architectural friction)

### F1 — Frozen `semantic_kind` vocab is missing pedagogical/notational kinds

`independent-variable`, `dependent-variable`, `mathematical-model`
were classified as `object` with `semantic_confidence: medium`.
None of those is really a mathematical *object* — they are
**pedagogical/notational devices**. The frozen vocab
(`object | property | operator | construction | criterion |
schema`) has no slot for this.

**Recommendation:** add `notation` and `pedagogical` to the
`semantic_kind` enum in v0.3.1, OR explicitly declare these
nodes out of scope and remove them.

### F2 — `GeneralityRelation` lacks `sibling` / `complementary` / `disjoint`

Used `incomparable` overloaded for three distinct semantic cases:
- power-function vs polynomial (genuine partial overlap)
- even-function vs odd-function (siblings, not complements)
- horizontal-shift vs vertical-shift (orthogonal-axis siblings)
- horizontal-stretch vs vertical-stretch (same)
- transcendental vs algebraic (true disjoint partition)

Five edges, three different real semantics, all collapsed to
`incomparable`. Loses information.

**Recommendation:** add `sibling` and `disjoint` (or
`complementary`) to the relation enum in v0.3.1.

### F3 — `definition.reflection` covers axis-reflection only

`proposition.inverse-graph-reflection` reflects about y = x, but
`definition.reflection` covers only x- and y-axis reflections.
Forced `dependency_confidence: medium` on that edge with an
explicit note. This is a real missing concept, not a schema bug.

**Recommendation:** generalize `definition.reflection` to
"reflection about a line" (covering axis cases as instances) OR
add `definition.reflection-about-line` as a more general node
with the existing one as `special_case_of`.

### F4 — Context-pack source-key collision/mismatch

`scripts/v03/make_context_pack.py --source "Cálculo de una
variable — Trascendentes tempranas"` produced a separate file
keyed by the lowercased title rather than updating the existing
`stewart-chapter-01.md`. The pack lists the 46 v0.3 nodes under
"Other-source nodes" rather than "this source's nodes", because
the source-key normalization (raw-string lowercased) did not
match the canonical short-key (`stewart`).

**Recommendation:** introduce a source-key registry
(`schema/v03/sources.yml`?) that maps canonical short-keys
(`stewart`, `rudin`, …) to their full titles, and have both the
context-pack tool and the snapshot/diff tools normalize through
it.

**Resolution (v0.3.1):** `schema/v03/sources.yml` registry
shipped. `schema.v03.load_source_registry()` exposes
`{key: entry}`; `make_context_pack.py` consumes it via
`_source_work` / `_source_author` (no more hardcoded dicts).
Validator emits a warning when `Source.work` does not match any
registered title, surfacing typos before they fork.

### F5 — Validator does not enforce locator presence

11 pre-existing nodes (extracted before the locator habit
solidified) still emit warnings. None blocks validation. This is
fine for the pilot but should harden for full rerun.

**Recommendation:** in v0.3.1, promote `locator-missing` from
warning to error for any node where `provenance.rerun_id`
indicates a v0.3 extraction.

**Resolution (v0.3.1):** `_check_warnings` now promotes
locator-missing to a hard error when `provenance.rerun_id` is
populated. Backfilled the 11 §1.1 foundation definitions with
subsection locators (Notación/Gráfica/Funciones definidas por
partes/Simetría/Crecientes y decrecientes). Post-fix:
0 errors, 0 warnings, 46 nodes / 95 edges (unchanged).

### F6 — `Proof.uses[].role` enum is restrictive vs natural usage

LLM extractor twice produced `role: lemma` for an external
proposition cited as a key step (proof.change-of-base,
proof.laws-of-logarithms). Validator rejected — correct enum is
`essential`. Not a schema bug, but a friction point: `lemma_local`
exists for *local* lemmas, while `essential` is the catch-all.
The naming is non-obvious.

**Recommendation:** clarify in policy 04 that external lemma /
proposition citations should use `essential`, and add the example
explicitly in EXTRACTION_PROMPT.md.

### F7 — `depends_on.role` enum: `uses` is not a member

LLM produced `role: uses` four times in this batch. Validator
rejected — must be `uses_concept`. Same kind of friction as F6.

**Recommendation:** EXTRACTION_PROMPT.md should enumerate the
exact strings inline; relying on policy-doc lookup is error-prone.

### F8 — `derived_from` was always `[]` for this pilot

No bundle splitting was needed in Ch1 (no v0.2 bundle definitions
to migrate). The `derived_from` field is therefore unexercised.
For Ch2+ we should expect to use it (e.g. limit-laws bundle).

## 6. Pilot verdict

**The v0.3 architecture survived contact with real extraction
pressure.** All eight findings above are concrete, fixable, and
do not invalidate the schema design. The two-layer dependency
graph, the six-axis quality model, the snapshot/diff/rerun
pipeline, and the canonical templates all worked as designed.

**Recommended next step before full v0.3 rerun:** ship a v0.3.1
schema patch addressing F1, F2, F6, F7 (additive enum extensions
+ EXTRACTION_PROMPT.md hardening). F4 (source-key registry) and
F5 (locator-required) can ship together as a tooling/policy patch.

F3 (reflection generality) and the multi-source merge candidates
in §4 are content-level concerns and should be handled during
the corresponding chapter reruns, not as schema changes.
