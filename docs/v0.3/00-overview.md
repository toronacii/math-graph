# 00 — Overview

## What v0.3 is

v0.3 is a **schema and process redesign** that prepares MKG for its first
semantically mature regeneration. It is not a re-extraction by itself; it
is the architecture against which a re-extraction will be performed.

## Why now

v0.2 succeeded as a prototype:

- The Statement → Proof → Statement model works.
- Multi-source reconciliation works.
- Context packs and retrieval-oriented extraction work.

v0.2 also exposed real limits that block scaling beyond calculus + early
real analysis:

1. **Single overloaded `confidence`** — cannot express "extraction is
   reliable, but the dependency list is incomplete".
2. **Flat `uses` list** — no role, no locality, no implicit/explicit
   distinction, no per-direction accounting.
3. **No definitional dependencies** — definitions cannot depend on other
   definitions, even though many of them obviously do.
4. **No ambient context** — identically-named results in different
   structures (R vs metric space vs topological space) get conflated.
5. **No LaTeX lifecycle** — 89 statements have no LaTeX, and there is no
   way to mark them as "intentionally informal" vs "needs formal form".
6. **No translation provenance** — bilingual entities cannot record which
   language is the original and which are derived translations.
7. **Coarse source locators** — 550 source records lack any page or
   theorem-level pointer.
8. **Status is binary in practice** — every entity is `draft`.
9. **No rerun mechanics** — there is no notion of snapshot, redirect,
   derived-from, or migration report.

The 2026-05-11 audit report quantifies these and proposes the structural
fixes that v0.3 implements.

## What v0.3 is NOT

- Not a theorem prover.
- Not a formal proof AST.
- Not an ontology engine.
- Not a replacement of YAML, SQLite, or the basic graph model.
- Not a guarantee of mathematical correctness — only of
  *auditability* of mathematical correctness.

## What v0.3 is willing to break

- Backwards compatibility with v0.2 YAML on disk.
- Existing IDs, when a more general node supersedes a specialized one.
- Visualization payload shape (a parallel `generated/v0.3/graph.json` is
  produced; the viewer is then re-pointed once the rerun completes).

## What v0.3 keeps

- YAML as the source of truth.
- One file per entity.
- Statement → Proof → Statement at the level of *derivations*.
- The repository layout (`data/statements/`, `data/proofs/`, `sources/`,
  `generated/`, `reports/`, `milestones/`).
- The pipeline shape: load → validate → SQLite → graph outputs.

## Top-level outcome

After v0.3 is in place and the rerun executes, the project should be able
to answer questions like:

- *Which theorems depend on completeness of R?*
- *Which proofs use a notion of supremum only as notation, vs as
  existence?*
- *How many distinct concepts are bundled inside this hub definition?*
- *Which statements have an audited mathematical formulation, and which
  are still extraction-confidence-only?*
- *If we redirect this id, which downstream proofs are affected?*
- *Which translations were generated by an LLM and never reviewed?*
- *In which ambient structure is this theorem stated?*

None of these are answerable in v0.2 without manual inspection.
