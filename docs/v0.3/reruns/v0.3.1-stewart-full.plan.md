## Acceptance criteria

A chapter is complete when:

1. `uv run mkg-validate` exits 0 against the chapter's contributions.
2. `uv run mkg-build` regenerates `generated/v0.3/{graph.json, math_graph.db, ...}` without errors.
3. Every emitted entity carries:
   - `schema_version: "0.3.1"`,
   - `provenance.rerun_id: "v0.3.1-stewart-full"`,
   - `language.original: es`,
   - exactly one `is_original: true` per multilingual block,
   - at least one `sources[]` entry with `work`, `chapter`, and either
     `theorem_label`, `section`, `page`, or `locator` populated
     (locator-integrity rule under rerun mode).
4. Status: every entity at `extracted` (no auto-promotion).
5. `quality.dependency_confidence` is set (not `null`) for every proof
   and for every statement carrying `depends_on` edges. Other axes set
   when evidence allows; `null` permitted when unassessed.
6. Per-chapter reports under `reports/v0.3.1-stewart-full/chapter-NN-*`:
   - `chapter-NN-statistics.yml`,
   - `chapter-NN-structural-analysis.md`,
   - `chapter-NN-weak-dependencies.yml` — with the new requirement that
     "no weak dependencies" is reported separately from
     `semantic_dependency_audit_status`, per the 2026-05-11 audit.
7. Snapshot at chapter milestones:
   `uv run mkg-snapshot --label v0.3.1-stewart-full-chNN`.
8. Final aggregate snapshot: `v0.3.1-stewart-full`.

## Architectural priorities (from the 2026-05-11 audit)

The Stewart rerun is also the first opportunity to apply the audit
recommendations within the v0.3.1 budget. Specifically:

- Use `definition.supremum`-style nodes via `role: notation` only.
  Existence-of-supremum proofs MUST cite a completeness statement via
  `role: existence`. Stewart treats reals informally, so this rule is
  observed when Stewart's text invokes the LUB property (rare in Ch1–2
  but binding by Ch11 series).
- Prefer atomic definition nodes over textbook bundles. When Stewart
  bundles concepts in a single boxed definition, split into separate
  YAML files and link them via `Statement.depends_on`.
- Use `Proof.uses[].role` precisely: `essential` for cited derivation
  steps; `notation`, `definition`, `existence`, `background`, `implicit`
  per the EXTRACTION_PROMPT taxonomy. Do not collapse roles.
- Statement `quality.dependency_confidence` is honest: high only when
  `depends_on` is genuinely complete; medium when a known concept is
  bundled in a definition not yet split; low when audit pending.
